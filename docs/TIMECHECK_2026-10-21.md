# 答非所问残项：台词自创时间 → 数字白名单机检（2026-10-21）

> 上一轮 8 条反馈里第 8 条「答非所问」的状态是**主因已修、仍有残项**：模型会自己造时间。
> 实测原案（`docs/review/dialogue/dialog_fix_after.json`，用户问「等了多久了？」）：
>
> ```
> 从早上七点开始……大概四个半小时了吧。他没说过会晚到，所以我只知道这个时间。
> ```
>
> 事实表是「跟那个人说好十点半，现在快十二点了」。她把自己**等了 4.5 小时**、
> **从早上七点开始**这两件从没发生过的事说得像回忆——句子通顺、没有语病，
> 但观众一对照就发现"她在编"。这类错法不会触发原有的任何闸门（不跑题、不复读、
> 没有英文、没反问），所以上一轮只能靠提示词劝，服从率不够。

## 0. 结论

1. **加了机检**：`app/director.py` 新增时间白名单（`_time_hits` / `time_audit` /
   `Plan.gate_check` 集成）。白名单来自卡包事实表（`facts` + 各拍既定台词），
   自动抽出「十点半 / 快十二点 / 三年 / 这半年」，**不硬编码**。
2. **两档判罚**（关键设计，见 §2）：钟点一律硬判 → 走已有「整段重写一次 → 再用确定性兜底」；
   环境铺垫里的时长只留痕进观测面板、不重写。这样既不放过真编造，也不让每轮白付一次重写。
3. **在 173 条真跑台词上复核**（12 批历史对话，不是新造的例子）：
   硬判 2 条、**都是真编造**；软档 5 条（「雨停了快一个小时」这类环境时长）；
   事实表原句 **0 误杀**。
4. 单元用例 **22 项全过**，含负控（自创必须被拦）与反负控（白名单为空时检查器不得误杀）。

## 1. 它到底查什么

| 类型 | 例子 | 规范化 | 判法 |
| --- | --- | --- | --- |
| 钟点 | 早上七点 / 十一点半 / 十二点 / 09:40 | `c:420` `c:690` `c:720` | **一律硬判**（白名单外即违规） |
| 她的时间线时长 | 我在这里坐了四个半小时 / 打烊快两个钟头 | `t:270` `t:120` | 分句里出现「我 / 等 / 约 / 说好 / 坐 / 上班 / 打烊 / 一直」才硬判 |
| 环境铺垫时长 | 雨停了快一个小时 / 这雨停了快三小时 | `t:60` `t:180` | **软档**：只写观测面板，不重写 |
| 无数字时长 | 半年 / 半个月 / 半小时 | `y:0.5` `mo:0.5` | 半年/半个月同"时间线"规则；半小时属口语填充，放行 |
| 口语填充 | 十分钟 / 一会儿 / 半天 / 两天 / 一杯 / 两个人 | — | 放行（`_DUR_FREE` + 不匹配就不报） |

白名单自动从事实表抽：`facts` 里的「说好十点半，现在快十二点了」「三年前也是这样的雨」
「这半年在拍雨后的城市」→ `{c:630, c:720, y:3, y:0.5}`。取不到 persona 时
**失败放行**（白名单为空 = 检查器静默），宁可漏检一次，也不让"十点半"被误杀成违规后
每轮重写 3–9s。

## 2. 为什么要分两档（这是本轮最关键的判断）

第一版是"只要不在事实表里就硬判"。拿上一版的 173 条真台词一跑，机检响 7 次：

| 命中 | 原句 | 判断 |
| --- | --- | --- |
| 一个小时 ×3 批 | 「雨停了快一个小时，地上还是湿的。」 | 环境铺垫，和事实表**不冲突** |
| 三小时 ×2 批 | 「这雨停了快三小时了。」 | 同上 |
| 八点 | 「你也得早点走，八点前到公司就行。」 | 钟点，编了对方的作息 → 该拦 |
| 早上七点 + 四个半小时 | 上面那个原案 | 和「十点半」直接打架 → 必须拦 |

硬判 7/173 = 4% 的轮次会触发整段重写，每次 +3~9s——**这正是上一轮被骂的首句延迟**。
所以按"这个时间是不是在说她自己的时间线"分档（`_SELF_TIME`）：环境时长软档留痕，
钟点与她自己时间线上的时长硬判。复核后硬判占比 **1.2%**，且命中的两条都是真编造。

### 3.4 端到端：真的接在首句闸门上（注入法，因为真模型很少编时间）

先说明**没测到什么**：今天用 6 条专门诱导她报钟点的问题（「你从几点开始等的？」「现在几点了？」
「你在这儿坐了几个小时了？」「末班车几点？」+ 2 条正常对照）跑真实链路，**时间闸门一次没响**——
她选择岔开话题而不是编时间（`tools/qa/timecheck_probe.py`，对照轮误杀 0）。这不是"检查器没用"，
而是"真模型很少撞上"：183 条历史真台词里也只撞上 2 次。

所以照项目里已有的 `gate_fail` 注入做法，加了 `time_fail` 注入：把一句**已知编造**的台词交给
**真实的** `plan.gate_check`（不是伪造违规），如果白名单失效，日志里会换成
「注入故障：时间白名单没有生效（这是失败，不是通过）」，可区分"没测到"与"通过"。

```
POST /api/debug/inject {"session_id": "...", "time_fail": true}
POST /api/turn        {"text": "等了多久了？"}
→ logs/turns.jsonl:
  "首句闸门拦下（时间「早上七点」不在事实表里（只说过：三年、半年、十点半、十二点），
   不要自己编钟点或时长），整段重写"
  gate_rewrites: 1
```

这条链路和"首句答非所问→重写→兜底"是**同一个调用点**（`app/main.py` 的 `plan.gate_check(...)`，
首句闸门里判、失败就整段重写一次）。`tools/qa/api_test.py` 19/19 仍全过。

命中后走的是**已有的**闸门路径（`app/main.py` 首句闸门）：丢掉这轮已生成内容 →
`generate_blocking` 整段重写一次 → 仍不过用 `plan.fallback`（这一拍本来该说的确定性台词）。
没有新增一次模型调用以外的东西；机检本身是纯正则，单次 <1ms（`plan.notes` 里也不留大对象）。

## 4. 提示词侧同时收紧了（减少重写概率）

`Plan.prompt_block()` 末尾那句从「整轮不超过 N 字」扩成：

```
整轮不超过 {max_chars} 字，只写你会说出口的话。时间只用事实表里的说法，不要自己编钟点或时长。
```

它是**唯一事实源**：白名单在 `facts`，提示词说"只用事实表里的"，机检兜底——
三者同源，不会出现"提示词说一套、闸门查另一套"。

## 5. 还差什么 / 边界

1. **只覆盖第一、二句**：闸门只在首句/前两句上硬判；如果编造的时间落在第三句以后，
   只进 `late_checks`（整段复核，写观测面板、不重写）。这是刻意的：已经念出去的句子
   重写会让字幕/音频对不上，代价比收益大。
2. **钟点以外的相对时间没查**：「后来 / 那天 / 那阵子」这类叙述性时间不可机检，
   仍靠事实表 + 提示词。
3. 卡包换角色时要重新确认 `facts` 里的时间写法能被 `_time_hits` 认出来
   （跑 `tools/qa/test_timecheck.py`，它会打印当前白名单）。
