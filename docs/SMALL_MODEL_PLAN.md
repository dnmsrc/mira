# 为什么这个场景不需要 25B：导演层 + 小模型（2026-10-20 下午）

> 上一轮我给的答案是「换 25B」。那是把模型当万能药：同样的提示词喂给 4B 不行，
> 就换一个大五倍的。这个判断是错的——**4B 答不好不是因为它笨，是因为我让它同时
> 干四件事**：读 1.2k 字人设、判情绪/事件、想起你刚说的名字、守住别写旁白。
> 它没有能力在这些目标之间做优先级，于是最先丢掉的是最不显眼的那个：
> 「先回答对方真正问的问题」。
>
> 这一轮的答案是：**把「想说什么」从模型手里拿走，只留「怎么说」给它**。

---

## 1. 结论先放这儿（4B，本机 4090，六轮固定脚本）

| 轮次 | 用户说 | 4B 现在答 | 生成耗时 | 首包音频 |
| --- | --- | --- | --- | --- |
| 1 | 你好，你叫什么名字？ | Mira。在这儿等一个人。 | 0.4s | 394ms |
| 2 | 你一个人坐这儿，是在等谁吗？ | 说好十点半来的那个人。现在快十二点了。 | 0.5s | 424ms |
| 3 | 我叫张伟，今天加班到十一点，手机也快没电了。 | 张伟。你刚说十一点下班，可现在都十二点了？ | 2.2s | 400ms |
| 4 | 你还记得我叫什么吗？ | 张伟。你刚才说的。 | 1.9s | 493ms |
| 5 | 你为什么要在这种天气里等人？ | 说好十点半来的那个人。我没给他打电话。 | 0.6s | 484ms |
| 6 | 能给我看看那张照片吗？ | 在雨衣内袋里，边角被摸软了。 | 0.6s | 566ms |

同一脚本在改造前（纯提示词 + 4B）的关键失败：

```
U: 你还记得我叫什么吗？   → 记不清了。但我见过你穿那件深蓝雨衣，是三年前的雨夜。   ← 记忆里明明有"张伟"
U: 你为什么在这种天气里等人？→ 不是在等人。我拍雨后的城市，已经四十七个晚上了。   ← 答非所问
U: 你在等谁？             → 不是。我刚看到门没关，就进来坐了。                  ← 拿场景道具岔开
U: 你叫什么名字？          → 我叫 Mira。在等一个人，大概七点前到。               ← 编了卡包里没有的时间
```

**改造后 6/6 轮通过机检（0 违规），单轮模型耗时 0.4–0.6s。**
25B（上一轮方案）在同一脚本上是 4.0–7.1s 一轮——慢的不是模型，是这个任务本来就不需要它。

## 2. 根因：我让一个 4B 同时干了四份工

1. **规划**：「先回答再延伸 / 不想说就挡回去 / 这拍能松口什么」——这是对话规划，
   大模型在做隐式规划，4B 做不了。证据：同一句话说「别用天气代替回答」，它下一轮照做。
2. **记忆检索**：「他刚才说他叫什么」——答案其实就 20 行前，但 4B 不会去找，
   它只会即兴编一个（或者像上面那样说「记不清了」）。
3. **事实一致性**：卡包里的时间是十点半，它说七点半——因为提示词里**没有给它可用的数字锚点**，
   它只能从最近见过的词里抓一个凑。
4. **格式纪律**：首行 JSON 指令 + 旁白过滤 + 长度限制，占掉它本就不多的注意力。

这四件事里有三件**本来就是确定性的**：问句类型只有几种、事实在会话状态里查得到、
该不该松口由节拍决定。把它们交给模型的概率去赌，是设计错误，不是模型太小。

## 3. 做法：`app/director.py`（导演层）

纯 Python、零模型算力、零网络，每轮在生成前跑一次，三件事：

### 3.1 判意图（正则，毫秒级）

`recall`（考你记不记得）/ `self`（你是谁）/ `why`（为什么）/ `wait_who`（在等谁）/
`photo`（想看照片）/ `greeting` / `volunteer`（对方刚自报信息）/ `default`。

> 踩过的坑：「你为什么一个人在这等」既命中 `why` 也命中 `wait_who`，先判 `wait_who`
> 就退回同一句「说好十点半的人」，看起来像复读。**疑问词优先级要高于关键词**。

### 3.2 给出「这一轮要传达什么」（内容钉死，措辞放开）

不是写死台词，是给一句**事实骨架**，例如：

```
这一轮要传达的意思（意思不许改，用你的话说，不要新增事实）：约好十点半，他一直没来。我没给他打电话。
```

4B 拿到这个，输出就是 `说好十点半来的那个人。我没给他打电话。` —— 她的语气还在，
但不会跑题。这一条是整次改造里效果最大的一步：**模型从「想内容」变成「改口吻」**。

### 3.3 机检 + 兜底（关键轮才付这个代价）

`Plan.check(reply)` 检查：必须出现的名字、本轮禁用词（上一轮刚用过的场景道具 +
连用两轮的意象词）、字数、括号旁白、客服腔、跨轮复读（二字组重叠 >75%）。

- **关键轮（记得我名字 / 你是谁）**：不流式，先整段生成 → 校验 → 不合格把违规原因
  写回去重写一次 → 还不行就用确定性兜底句（`张伟。……记得，你刚才说的我都记着。`）。
  代价 0.3–0.5s，换来「这两轮永远不会演砸」。
- **普通轮**：照旧流式，首字延迟不变。

### 3.4 事实表（`persona.py`）

卡包里 `character.facts` 一直有 8 条具体事实（二手 OM-1、拍第四十七个晚上、说好十点半……），
但**从来没进过提示词**。现在压成一行一条的「你今晚记得的事」，并加一条硬规则：
**数字和物件只能从这张表里取，表里没有就说记不清，不许编。**
编造的「七点半末班车」就此消失。

### 3.5 顺手修掉的两处「自己造谣」

- 事实抽取模板把「加班」和「末班车」合在一条里 → 角色会说「你要等末班车吧」，
  那是**我们塞给她的**细节，不是观众说的。拆成一条规则一条事实。
- 卡包 `secret` 里写着「只绕着照片、雨、末班车打转」→ 这就是她每轮都提雨和末班车的原因。
  改成「被问到时只说一半」，不再给模型示范重复词。

### 3.6 开场白用卡包定稿，不交给模型

开场那一句决定第一印象，且 `start.ps1` 启动时已把卡包台词预热进 TTS 缓存。
现在 `kind == "open"` 直接用卡包里的定稿台词（附首行指令），首包从 1.9s 降到 300ms 段。

## 4. 什么时候仍然需要大模型（诚实边界）

这套做法的前提是「场景可以被确定化」。它成立的范围：

- ✅ 人设固定、节拍有限、事件的触发条件可枚举（本场景就是这一类）
- ⚠️ 观众聊到导演层没预设的话题时，只有 `default` 那条通用指令兜着——
  这时 4B 会明显比 25B 平，属于**可接受的降级**（面子和里子都还在）
- ❌ 开放式长对话、需要总结剧情/记住十几轮细节、需要即兴玩梗、多角色关系推理——
  这些不适合用这套压缩，直接上 25B 更省事

所以 `LLM_MODE` 仍然保留三档：`llama`（默认，4B + 导演层）/ `strata`（25B，对照）/
`mock`（零依赖）。观众体验靠导演层，模型档位只是「自由发挥时的上限」。
