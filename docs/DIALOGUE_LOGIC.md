# 对话逻辑：结构、数据流与判据

> 这份文档只讲**一轮对话是怎么被决定出来的**：谁决定说什么、谁决定怎么说、说错了怎么办。
> 表演层（表情/动作/语音的时序）在 [PERF_CONTRACT.md](PERF_CONTRACT.md)，素材在
> [ASSETS_REVIEW.md](ASSETS_REVIEW.md)，这里不重复。

页码/行号以 2026-10-20 的工作区为准。

---

## 0. 一句话

**「说什么」由确定性的 Python 决定，「怎么说」才交给 4B 模型，说出来之后先用正则验一遍再放给观众听。**

这句话不是口号，它决定了下面每条数据流的形状：凡是能被机检的东西（问的是哪件事、
该给哪个事实、名字有没有说错、有没有复读、有没有旁白）都不进模型；模型只保留它真正擅长
的一件事——把已经定下来的意思说得像人话。

## 1. 一次 turn 的完整路径

```
用户这句话（文本 / STT 转写）
  │
  ├─① 记忆抽取        extract_facts()              main.py:411
  │     正则抽「他叫什么 / 加班到很晚 / 手机快没电 / 被雨淋了」，进 Session.user_facts
  │
  ├─② 剧情闸门        beat_jump() / beat_advance() persona.py:127/146
  │     用户问到后面拍的话题 → 剧情直接跳过去（内容决定节奏，不是计时器）
  │
  ├─③ 导演层          director.plan_turn()          director.py:562
  │     判「问的是哪件事」(槽位) → 产出本轮 Plan：content / topic / anchors / forbid
  │                                              / max_chars / must_ask / fallback / gate
  │
  ├─④ 提示词装配      persona.render_system_prompt() persona.py:248
  │     固定角色卡前缀（可命中 KV cache）+ 动态节拍尾巴 + **Plan 指令块放最末尾**
  │
  ├─⑤ 生成            LLM 流式输出「首行 JSON 指令 + 换行 + 台词」
  │     header_probe() 按括号配对扫描首行，JSON 没闭合前一个字都不送 TTS
  │
  ├─⑥ 白名单 / 闸门   finalize()                    main.py:757
  │     sanitize 收敛枚举 → 本拍 pin → guard_story 拦早到的事件 → 去重 → 关键词补事件
  │
  ├─⑦ 首句闸门        Plan.gate_check()             main.py:741-893
  │     第一句完整时立刻校验（点题/硬禁词/复读/旁白）；不过 → 丢内容 → 整段重写一次
  │     → 再不过 → 用 plan.fallback（这一轮本来就该说的那句事实）
  │
  ├─⑧ TTS + 字幕      逐句合成、按序下发、按句间气口插停顿     main.py:544 tts_worker
  │
  ├─⑨ 表演层          perf.*                        app/perf.py
  │     把「什么时候换脸 / 什么时候做动作 / 什么时候看门口」排到音频时间轴上
  │
  ├─⑩ 落地复核        Plan.gate_check(first=False)   只记日志、不重写（避免二次延迟）
  │
  ├─⑪ 回写            Session.recent / plan_contents / asked_topics / history
  │     history 里存的是「首行 JSON + 台词」，让模型下一轮看到自己确实在守协议
  │
  └─⑫ 节拍推进        persona.beat_advance()        话题命中够次数 / 事件 / 轮数上限
```

对应 `/api/turn` 的 NDJSON 事件流：

```
state(thinking) → turn_start → directive → pacing → perf(rev1) → subtitle_partial…
→ state(speaking) → audio(第1句) … → perf(rev2) → reply → suggest → done
```

`done` 里带本轮的可审计字段：`plan.{intent,topic,violations,must,anchors}`、
`gate.{checks,rewrites,ms,wait_ms}`、`first_text_ms`、`first_audio_ms`。

## 2. 六层的分工

| 层 | 文件 | 回答的问题 | 是否机检 |
| --- | --- | --- | --- |
| 记忆 | `main.py:extract_facts` | 他说过什么，我得记住 | 正则，可单测 |
| 剧情 | `persona.py:beat_*` | 现在能说到哪一步 | 阈值（话题命中/事件/轮数） |
| 导演 | `director.py:plan_turn` | **这一轮问的是哪件事、该传达什么事实** | 纯函数，可复现 |
| 提示词 | `persona.py:render_*` | 怎么把上面两层塞给模型 | — |
| 校验 | `director.py:gate_check` + `main.py` | 说出来的是不是答非所问 | **是，正则** |
| 表演 | `app/perf.py` | 什么时候换脸/做动作/看门口 | 锚点断言（`perf_probe.py`） |

## 3. 逐层说明

### 3.1 记忆：只存「能被追问的具体物」

`_FACT_RULES` 是一组正则，每条对应一条事实（`他叫X` / `他今晚加班到很晚` / `他手机快没电了` …）。
两个细节是踩坑换来的：

- `_valid_name()` 过滤问句被当成名字：用户问「你还记得我**叫什么**吗」，正则曾抽到「什么吗」，
  记忆里多了一条「他叫什么吗」，下一轮提示词把它当已知事实喂给模型。
- 一条规则一条事实：早先把「加班」和「末班车」合在一条里，角色就跟着说「你要等末班车吧」——
  那是模板塞给她的，属于**我们编的**细节。

### 3.2 剧情：内容触发，而不是计时器

- `beat_jump()`：用户一句话问到后面拍的话题（照片/相机/末班车），剧情**直接跳过去**。
  这是对「互动」最关键的修正：上一版用「第 4 拍才允许拿照片」把事件锁住，用户一进来就问
  「能看看那张照片吗」，角色只能糊过去——观众看到的就是答非所问。现在反过来让提问决定节奏。
- `beat_advance()`：视觉事件 / 话题命中 ≥ `min_hits` 且轮数 ≥ `min_turns` / 轮数到 `max_turns` 兜底。
  三个阈值都在卡包里，不在代码里。

### 3.3 导演层：从「意图类别」到「问的是哪件事」

这一层是这一版改动最大的地方，也是「答非所问」的根因所在。

**旧结构（有问题）**：`_INTENT_RULES` 只有 7 条规则，而且 **意图 → content 是一对一静态映射**。
「你为什么这么晚还在外面」和「你为什么不去找他」都会命中 `why`，拿到同一句
「约好十点半，他一直没来」——后一个问题**在结构上就没有被表示**，模型再强也只能答另一件事。

**新结构**：

1. **槽位判定**（`director.py:45-72`，顺序即优先级）：先判「这句话问的是哪件事」——
   `request`（要联系方式）/ `offer`（提议帮忙）/ `why_not_go`（为什么不去找）/ `doubt`（是不是骗我）
   / `fear` / `coffee` / `how_home` / `howlong` / `where` / `photo` / `name` / `recall` / `self` …
   顺序有讲究：`offer` 必须排在 `request` 前面，否则「帮你打个电话」因为句子里有「电话」
   会被当成「索取号码」（实测踩过）；`why` 必须排在 `wait_who` 前面，否则
   「你为什么一个人在这等」会被当成「你在等谁」。
2. **每个槽位自带四件东西**：`content`（这一轮要传达的事实，只给意思）、
   `topic`（机检标签）、`anchors`（回答里必须点到的话题词）、`fallback`（确定性兜底台词）。
3. **没有槽位也有 content**：`default` + `react`（纯闲聊接话）都生成 content。
   旧版 default 只给一句元指令「先正面回应对方这句话」——4B 拿不到可说的东西，
   只能从最近见过的词里抓一个凑（实测编出「司机在后门等，十一点半到站」）。
4. **跨轮去重与反问**：`prev_contents` / `asked_topics` 会阻止连续两轮说同一件事；
   每 3 轮强制 `must_ask=True`（答完用半句话把话头交回去），避免她只是在被采访。
5. **硬边界可机检**：卡包规定「不要主动说出阿岸这个名字」，所以 `forbid=["阿岸"]`，
   出现即重写——这不是提醒模型注意，是真的会拦。

`Plan.prompt_block()` 把上面这些东西写成**最末尾**的指令块（`main.py:683`）。
放末尾是有意的：4B 对末尾指令的服从率明显高于开头，而 prefix cache 只要求前缀不变。

### 3.4 校验：首句闸门（这一版最关键的新机制）

流式生成和「事后校验」天然冲突：第一句一落地就进 TTS 了，等整段生成完再发现答非所问，
声音已经出去了。解法不是放弃流式，而是**利用 TTS 本来就有的等待**：

- TTS 是**按句**合成的（`take_sentences()` 要等到句号才切句），所以「扣住第一句先校验」
  的额外延迟 ≈ 0（只有几微秒正则）。**成功路径不加延迟**，`gate_wait_ms` 记的就是这个差值。
- 校验不通过时**先不判死**：`「不是。」`这种句子要等后面那半句，攒到第 2 句仍不过才判失败
  （挡话是允许的，只是必须挡对题）。
- 判失败 → 丢掉这轮已流式生成的内容 → `generate_blocking()` 整段重写一次
  → 再不过 → 用 `plan.fallback`：那是这一轮**本来就该说的那句事实**，所以兜底也是对题的，
  不是「随便糊一句」。
- 重写期间不刷字幕（`gate_done` 之前不 emit `subtitle_partial`）：宁可晚 100ms 出字，
  也不要把一句马上要被重写掉的错话先糊到屏幕上。

`gate_check()` 的判据（`director.py:165`）：

| 判据 | 说明 |
| --- | --- |
| `anchors` 命中 | 回答里必须点到被问那件事的同义词组之一（允许挡，但挡要挡对题） |
| `forbid` | 硬禁词（如「阿岸」）出现即违规 |
| `must` | 必须逐字出现的内容（被问到名字时的名字） |
| 复读 | 与最近 3 句的二字组重叠率 > 0.8 → 违规 |
| 旁白 / 客服腔 | `（低头）`、`*叹气*`、`作为`、`很高兴为您`… |
| 长度 / 软禁词 | 只在整段复核时查，首句不查（首句只是整段的一部分，拿整轮字数卡会误杀） |

> 允许「挡回去」是刻意的：她有事不想说，这本身是角色的一部分。但**挡的话必须落在被问的那件事上**
> ——「你问这个干嘛」对，上来回一句「不是。等一个人」就不对，因为那是在答另一个问题。

### 3.5 提示词三段式

```
[固定前缀] 角色卡 / 场景 / 事实表 / 9 条说话纪律 / 输出格式（首行 JSON）
[动态尾巴] 第 N 拍 · 动机 / 可以松口 / 绝对不要说 / 对方已经知道 / 最近说过的台词
[本轮指令] 【本轮怎么做 · 优先级最高，覆盖上面所有说法】
           + 这一轮要传达的意思（意思不许改，用你的话说）
           + 回答必须点在这件事上（用得到这些词：…）
           + 答完用半句话反问他一个具体问题
           + 绝对不能说 / 这轮禁用这些词 / 字数上限
```

前两段每轮不变（可命中 KV cache），只有第三段变——所以每轮只需重新预填充最后一小段，
首包延迟从 2s+ 压到 1s 以内（`docs/SMALL_MODEL_PLAN.md` 有 Strata 实测）。

### 3.6 表演层（简述）

`app/perf.py` 把「反应延迟 / 语气词 / 换表情 / 做动作 / 看门口」排成一个带锚点的列表，
锚点是 `turn.start` 或 `s{i}.start|end`（第 i 句音频的开始/结束），客户端按**音频播放时钟**触发
（`app.js:PERF`）。这样画面和声音同一条时间轴，而不是「收到指令就换脸」。详见 `PERF_CONTRACT.md`。

## 4. 为什么是这个结构（而不是「换个更大的模型」）

4B 的问题不是不会说话，是**同时干太多活**：读 1.2k 字角色卡、判情绪、想起名字、守住「别写旁白」……
几个目标一抢注意力，它最先丢掉的永远是最不显眼的那个——「回答对方真正问的问题」。

所以把活儿拆开：需要**规划**的部分（问的是哪件事、该给哪个事实、能不能松口）是确定性的，
交给正则和查表；需要**措辞**的部分才是概率模型该干的。这也是这个场景不需要 25B 的原因：
25B 的收益主要在「开放话题的自由发挥」，而这一轮修的全是「有正确答案却被答错」的部分——
那部分换大模型只是把错误率从 45% 降到某个数，而确定性代码能把它降到 0（或者明确兜底）。

## 5. 这一版修掉的三个结构性毛病

同一套 12 句台词、同一个 4B（Qwen3-4B-Instruct-2507 Q4_K_M）、同一个 TTS，前后各跑两轮：

| 毛病 | 修之前的真实台词 | 修之后 |
| --- | --- | --- |
| 意图→content 一概而论 | 问「你为什么不去找他」→「没给他打电话。照片在口袋里，一直没发出去。」（答的是"为什么在这里等"） | 「不知道他在哪。问过没人知道。三年了，一直没找到。」 |
| default 轮没有 content | 问「要不我帮你打个电话」「你手机号码多少」「今晚怎么回去」「明天还要上班」四轮里三轮回同一句「不是。等一个人。说好十点半，现在快十二点了。」 | 「不用。……我要是想打，早就打了。你几点下班？」／「号码不给。你要找我，明天还来这儿就行。」／「住这条街，走回去十来分钟。」 |
| 只有 critical 轮机检 | 两轮 22 次提问，0 次重写、0 次兜底——错的话直接进 TTS | 所有提问轮走首句闸门；失败重写一次，再失败用对题的兜底台词 |

同一套 12 句台词、同一个模型、同一个 TTS，前后各跑多轮；判据**手写在 QA 脚本里**，
不复用运行时的 `gate_check`（避免"自己判自己"）。完整数据与判据定义见
[`docs/review/dialogue/report.md`](../review/dialogue/report.md)。

| 指标 | before | after（最终代码） |
| --- | --- | --- |
| 点题（11 个可判轮） | 5/11、4/11（两轮） | **11/11、11/11** |
| 给了具体信息 | 6/11 | 11/11 |
| 复读 | 1–2 | 0 |
| 反问 / 把话头交回去 | 0 | 4（形态按轮次轮换） |
| 编造事实 | 有（「十一点半到站」） | 0 |

另有一组**不同台词**的真实 12 轮（`tools/qa/chat_probe.py`，在线上 8787 跑）用来防"只对
固定剧本调参"，实测暴露并修掉了两个槽位误判：

```
[7]「后来呢？他没再联系你？」  修前 →「号码不给。你要找我，明天还来这儿就行。」
                             修后 →「后来再没出现过。没消息，也没回来。……」
[9]「那你打算怎么办？照片要寄出去吗？」 修前 →（又把照片描述了一遍）
                             修后 →「还没决定。该不该寄出去，我也在想。你明天还来不来？」
```

> 这两个都是**槽位正则误伤**：`request` 里的裸「联系你」把"他后来有没有联系你"当成"我要不要
> 给你号码"；`photo` 抢在"打算/寄出去"前面。修法是收窄 `request`、新增 `followup` 与
> `choice` 两个槽位并排在它们前面——这也说明「判据写清楚」和「判据写对」是两件事。

## 7. 还没解决的（照实写）

1. **事实一致性没有机检**：仍会出现「第二杯」前后不一致、或者反问一个对方没说过的细节
   （「你上次说想试试苦的，是吗」）。现在只靠提示词里的「时间、物件、数字只能从事实表里取」。
   要真做，需要一张带槽位的世界状态表 + 事后一致性校验。
2. **闲聊轮（react）没有 anchors**，闸门只能查复读，偶尔会复读上一轮的某个意象
   （实测「外面好像又打雷了」→ 又提了上一轮的相机）。现在靠 `content` 引导 + 子句复读规则兜着。
3. **闸门只保证前两句对题**：后半句跑题只记日志、不重写（避免第二次延迟）。
4. **槽位覆盖不到"人味"的表达**：比如「我陪你等一会儿」这种带「陪」的提议，落在 `offer`
   之外，回答虽然对题但生硬（「你要是真想等，就坐吧——我没说走，我也没说要走」）。
5. **反问只做了形态轮换**，没有"内容不重复"保证（连着两位都是问对方几点下班仍可能发生）。
6. **兜底台词是固定句子**：命中率高但会重复，连续触发两次时观众能听出来。
7. 4B 仍会自创枚举值、偶尔夹英文词（例如把 `tonight` 混进中文），前者被白名单收敛、
   后者由闸门的 ASCII 规则拦下重写，都会在 `fixes` / `notes` 里留痕——**不假装是模型说对了**。
8. **首行 JSON 解析失败仍会整段当台词**（遗留风险，未处理）。
